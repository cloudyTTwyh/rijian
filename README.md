# 日笺 · 纯本地日记本

一个不联网、不要账号、数据全在自己手机上的日记应用。做成了 PWA，用 Safari 加到主屏幕就能像普通 App 一样用。

---

## 一、文件结构

```
diary-app/
├── index.html        页面骨架
├── style.css         全部样式（纸墨配色、宋体排版）
├── app.js            全部逻辑（存储、编辑、日历、搜索、锁屏、导入导出）
├── sw.js             Service Worker，负责离线缓存
├── manifest.json     PWA 清单（图标、名称、启动方式）
├── version.json      当前版本号，供「检查更新」比对
├── icons/            图标（180 / 192 / 512）+ 生成图标的源文件
└── README.md
```

整个目录不到 1 MB，没有依赖任何第三方库，没有 CDN。

---

## 二、本地预览

在这个目录下起一个静态服务器：

```bash
python -m http.server 8788
```

然后浏览器打开 `http://localhost:8788/index.html`。

> 想清空数据重来，在浏览器控制台执行 `indexedDB.deleteDatabase('rijian-db')` 后刷新。
> 想灌演示数据，跑 `_dev/` 里的测试脚本，它会通过 `fixtures.mjs` 注入。

## 三、装到 iPhone

必须有一个 **HTTPS 网址**——用 `file://` 或局域网 `http://` 都不行，
因为 Service Worker 和「申请永久存储」这些能力只在安全上下文里可用。

拿到网址之后：

1. **用 Safari 打开**（必须是 Safari，Chrome 或微信内置浏览器加的图标不是真正的 Web App）
2. 点底部**分享**按钮
3. 滑到「**添加到主屏幕**」
4. 改名「日笺」→ 添加

之后主屏幕就有一个独立图标，点开全屏运行，没有地址栏。

## 四、有几条路可以拿到网址

| 方案 | 成本 | 说明 |
|---|---|---|
| WorkBuddy 一键发布 | 0 | 最快，链接归平台 |
| GitHub Pages | 0 | 免费、永久，推荐长期用 |
| 自己的服务器 + 域名 | 域名年费 | 最稳，但没必要 |

部署时把整个 `diary-app` 目录传上去即可，入口是 `index.html`。

## 五、数据存在哪

全部存在手机浏览器的 IndexedDB 里，库名 `rijian-db`，**不上传任何服务器，App 里没有一行网络请求代码**。

三道保险：

1. **`navigator.storage.persist()`** —— 首次打开就申请永久存储。授予后系统不会自动清理。
   设置页里「永久存储」显示「已保护」就是生效了。
2. **备份提醒** —— 首页顶部会显示「已经 N 天没有备份了」，点一下直接导出。
3. **导出文件** —— 设置 → 导出为 Markdown / 导出完整备份。文件落到「文件」App，
   你再 AirDrop 或数据线传到电脑。

> 注意：iOS 里「加到主屏幕的 Web App」**不受 Safari 那个 7 天清理规则约束**（WebKit 官方明确豁免）。
> 会丢数据的真实情况只有三种：磁盘快满了、你删掉了主屏幕图标、你手动清了浏览器数据。

## 六、功能清单（第一版）

- 写日记：日期 + 标题 + 正文，支持加粗 / 斜体 / 列表 / 插图
- 自动保存：停手 2 秒自动落库
- 时间线：按月分组，带摘要和缩略图
- 日历：有日记的日子有底色，点空白日子可以直接「写一篇」
- 搜索：全文检索，关键词高亮
- 删除：编辑器右上角垃圾桶，删除进垃圾箱，可恢复
- 垃圾箱：可单条恢复 / 彻底删除 / 清空
- 密码锁：4 位数字，可在设置里设置 / 修改 / 关闭
- 导出：Markdown（带图片）/ 完整 JSON 备份 / 从备份恢复
- 检查更新：比对线上版本号，一键清缓存重载
- 离线：断网照常使用

**还没做**（按之前定的取舍）：分类、农历、信纸、多字体、云同步、分享、每日一文。

---

## 七、几个需要知道的设计取舍

- **富文本只留了加粗、斜体、列表**。颜色、字号、信纸这些不做，因为它们没法用 Markdown 表达，
  导出时会丢格式或变成一堆 HTML 标签。界面上的「美」靠排版实现，不靠文字格式。
- **没有云同步**。数据只在这台设备上，靠导出文件自己搬。这是有意的——云同步意味着要账号、要服务器。
- **密码锁是本地校验**，4 位数字。它的作用是「防止别人拿起来随手翻」，不是抗暴力破解。
  哈希存在本地数据库里，不解锁拿不到日记内容（但懂技术的人能直接读 IndexedDB，这一点要知道）。

## 八、想改的话

- 换配色：改 `style.css` 顶部 `:root` 里的变量
- 换名字：`manifest.json` 的 `name` / `short_name`，`index.html` 的 `<title>` 和 `apple-mobile-web-app-title`
- 换图标：替换 `icons/` 下三张 PNG（180×180 / 192×192 / 512×512），或改 `icons/icon-src.html` 后重新截图
- 加功能：`app.js` 按模块分段，注释齐全

改完记得把 `sw.js` 里的 `CACHE = 'rijian-v1'` 改成 `v2`，否则手机上会一直用旧缓存。

## 九、发布流程

**发布前检查清单**（已完成）：

- [x] 删除演示数据 `_seed.js` 与 app.js 里的 `[TEMP-DEMO]` 代码块
- [x] 缓存版本升到 `rijian-v5`
- [x] 全量回归测试通过（20 项）
- [ ] 选定托管方式（见第四节）

**步骤**：

1. 把整个 `diary-app` 目录上传到托管（不要只传 index.html，CSS/JS/图标/清单都要）
2. 确认地址是 `https://`，浏览器打开能看到应用
3. 手机 Safari 打开 → 分享 → 添加到主屏幕
4. 装好后断网试一次，确认离线可用
5. 设个密码，退出重进，确认能解开

**以后更新代码时**，三处版本号要一起改，缺一个都会出问题：

| 位置 | 当前值 | 作用 |
|---|---|---|
| `app.js` 顶部 `const APP_VERSION` | `'1.1'` | 应用自己认为的版本 |
| `version.json` 的 `"version"` | `"1.1"` | 服务器上的版本，供比对 |
| `sw.js` 的 `CACHE` | `'rijian-v6'` | 缓存桶名字，变了才会换缓存 |

前两个必须**完全一致**，否则「检查更新」会一直提示有新版。

改完上传，手机上打开 → 设置 → 检查更新 → 立即更新，它会清掉缓存并重载，不用等两次刷新。

> 版本号比对用的是「大于」：线上 `1.2` > 本地 `1.1` 才会提示。所以只能在版本号上往前改，不能回退。

## 十、已修的问题（留档）

| 问题 | 后果 | 处理 |
|---|---|---|
| 设密码时两遍输入总提示不一致 | 无法设置密码 | `setLockMode` 会清空暂存的第一遍密码 |
| 解锁拿明文比哈希 | 设了密码就永远打不开 | 改成 `hashPin(pin) === state.pin` |
| 清空正文后点完成 | 静默删除整篇日记 | 改为弹窗确认 |
| 导入的 HTML 直接 innerHTML | 可执行脚本（XSS） | 加 `sanitizeHtml` 白名单清洗 |
| 自动保存定时器没取消 | 退出后仍把内容写回去 | 关闭时清 timer |
| 从日历/搜索打开日记，返回却回首页 | 位置丢失 | 记录来源视图 |
| 透明 PNG 转 JPEG | 透明区域变黑 | canvas 先铺白底 |
| 编辑器没有删除入口 | 只能靠清空正文删 | 顶部加垃圾桶按钮 |
| 日历空白日期无法新建 | 补写日记很别扭 | 加「写一篇」按钮 |
| 导出超大 Markdown | 手机生成/下载可能失败 | 超 18MB 自动省略图片并提示 |
| 搜索遍历全部 HTML | 数据多时卡顿 | 改用保存时的纯文本字段 |

自动化测试在 `_dev/` 里：`test-full.mjs`（12 项主流程）、`test-extra.mjs`（8 项导出/导入/性能）、`test-lock.mjs`、`test-lock2.mjs`（密码锁）。改动代码后跑一遍再发布。
